# /korean-prose:review

`awkward-korean-reviewer` 에이전트의 얇은 래퍼입니다. 어색함을 보고하고, 모든 사실과 숫자, 영어 기술 레이블, 코드 블록, 링크, 경로를 그대로 보존한 KO 전용 재작성안을 함께 제시합니다.

사용자 호출 인자: `$ARGUMENTS`

<br/>

## 레인 결정 — 두 레인은 동급

어느 레인도 기본값이 아니고 어느 쪽도 보조가 아닙니다. 타겟이 무엇인지로 고릅니다.

- **레인 A — 한국어 Markdown**: body 가 한국어 산문 위주인 모든 `.md` — README, 문서 페이지, 블로그 포스트 초안, 설계 노트.
- **레인 B — bilingual YAML**: 문자열이 `{ ko, en }` 쌍으로 된 YAML 파일의 `ko:` 절반.

두 레인 모두에서 범위 밖: `en:` 절반, `*-en.md`, 영어 `.md`, 코드 블록, inline code, URL, 경로, 소스 파일 주석.

<br/>

## 모드 결정 — 가장 먼저 정할 것

| `$ARGUMENTS` | 모드 |
|---|---|
| 비어 있음, 경로, 디렉터리, "전체" / "전부" / "스캔" | **감사** |
| 붙여넣은 한국어 산문, 제안된 재작성, "이렇게?" / "이거 어때" / "어색해" | **판정** |
| 산문 **과** 경로 | 그 항목에 **판정**, 그 다음 감사를 *제안* — 부르지 않았는데 실행하지 말 것 |
| 경로 + "내가 고친 것들 봐줘" | **감사**, 단 파일 전체가 아니라 `git diff` 범위로 |

애매하면 한 줄로 묻고 **판정** 으로 기본 처리합니다. 원치 않은 감사는 스크롤해야 하는 텍스트 벽이고, 사용자가 넓게 원했던 판정은 후속 질문 한 번이면 됩니다.

**비어 있으면 두 레인 모두로 해석**합니다: `git diff --name-only` (및 untracked) 가 보고하는 한국어 `.md` **와** bilingual YAML 의 `ko:` 줄. 빈 호출을 Markdown 으로만 좁히면 많은 사용자가 가장 자주 편집하는 표면을 조용히 건너뜁니다.

<br/>

## 1단계 — `awkward-korean-reviewer` 에 위임

레인과 모드를 한 줄로 밝힌 뒤 호출합니다. 에이전트는 두 개의 패스를 돌립니다:

1. **토큰 패스** — 직역체 / 번역체 (`~에 있어서`, `~을 통해서` 남발, `의` 연쇄, 수동태 남발, 추상명사 + `~을 가지다`), 일본어식 한자어 (`검토 진행`, `~화 시키다`), AI 티 패턴 (`~하는 것이 가능`, `결론적으로`, 기계적 병렬, 이중 피동, `~하고,`), 조사 누락·오선택, 종결법 혼용, 시제, 외래어 표기, 호응 오류, 그리고 영어 개념 1:1 치환 사전.
2. **대조 패스** — 토큰 스캔으로는 볼 수 없는 findings, 그리고 깨끗한 토큰 스윕이 깨끗한 리뷰가 아닌 이유: **형제 구조 이탈** (형제와 모양이 다른 bullet 하나), **이웃 중복** (같은 논거를 반복하는 두 항목), **과장 드리프트** (근거는 `경감` / `방지` 인데 `최소화` / `차단` / `완전` 이라고 쓴 경우), **표기 일관성** 파일 전역 (`Pod` 대 `파드`), **용어 도입 관례** (다른 개념은 전부 풀어 쓰는 산문에 맨 영어 개념어 하나).

모든 대조 finding 은 근거를 함께 제시해야 합니다 — 대조한 형제 줄, 또는 두 개의 grep 카운트. 근거가 없으면 반증이 불가능하고 사용자가 확인할 수 없습니다.

<br/>

## 2단계 — 항목 단위로 적용

- **감사 모드 출력은 read-only 입니다.** 수정이 아무리 명백해 보여도 이 모드에서 편집하면 안 됩니다. 특정 항목을 적용하겠다고 제안하며 끝냅니다.
- **판정 모드는 적용 가능** — 단 전/후를 **전문으로** 보이고 (diff 조각 금지, `…` 생략 금지) 승인을 받은 뒤에만. 승인 1건은 항목 1건만 덮으며, 파일의 나머지는 절대 포함하지 않습니다.
- cross-file sync 는 편집의 일부입니다: 두 파일에 있는 `ko:` 문자열은 같은 턴에 둘 다 편집하거나 둘 다 하지 않습니다.
- YAML 편집 후에는 parse 체크를 돌리고 결과를 보고합니다.
- 커밋은 사용자가 할 다음 단계로 안내합니다. 에이전트는 커밋도, 푸시도, build 타겟 실행도 하지 않습니다.

<br/>

## 하드 룰

- `en:` 절반, `*-en.md`, 영어 `.md` 는 모든 모드에서 범위 밖입니다 — KO 변경에 맞추기 위해서라도 재작성하지 않습니다. KO 수정이 KO↔EN parity 를 깬다면 그렇다고 말하고 멈춥니다.
- pair / 구조 drift (두 사본 사이의 heading 개수, 코드 블록, 표 drift) 는 이 커맨드의 일이 **아닙니다** → `doc-mirror` 플러그인.
- 모든 재작성에서 사실, 숫자, 영어 기술 레이블, 코드 블록, 링크, 경로를 보존하고, 문서의 기존 톤과 register 에 맞춥니다.
- 지표, 인원수, 그 어떤 숫자도 지어내지 않습니다. 사실이 틀려 보이면 flag 하되 조용히 바꾸지 않습니다.
- heading, 섹션, 리스트 항목, 표 행을 추가 / 제거 / 재정렬 / 병합 / 분할하지 않습니다. 이것은 텍스트 전용 패스입니다.
