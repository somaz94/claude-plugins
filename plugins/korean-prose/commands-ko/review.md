# /korean-prose:review

`awkward-korean-reviewer` 에이전트의 얇은 래퍼입니다. 어색함을 보고하고, 모든 사실과 숫자, 영어 기술 레이블, 코드 블록, 링크, 경로를 그대로 보존한 KO 전용 재작성안을 함께 제시합니다.

사용자 호출 인자: `$ARGUMENTS`

<br/>

## 레인 결정 — 두 레인은 동급

어느 레인도 기본값이 아니고 어느 쪽도 보조가 아닙니다. 타깃이 무엇인지로 고릅니다.

- **레인 A — 한국어 Markdown**: body가 한국어 산문 위주인 모든 `.md` — README, 문서 페이지, 블로그 포스트 초안, 설계 노트.
- **레인 B — 한국어 YAML 데이터**. 파일명 목록이 아니라 파일을 보고 정합니다: `ko:` 키가 있으면 **bilingual**(`ko:` 절반만), 한글이 있는데 `ko:` 키가 없으면 **단일어 한국어**(저작 값 전부, 단 스크립트가 upstream 에서 재생성하는 블록은 제외). 스캐너도 같은 기준으로 나누므로 둘이 파일의 정체를 두고 어긋날 수 없습니다. 단일어 파일은 한국어가 수천 줄이라, 파일이 아니라 스윕할 블록을 지정하세요.

두 레인 모두에서 범위 밖: `en:` 절반, `*-en.md`, 영어 `.md`, 코드 블록, inline code, URL, 경로, 소스 파일 주석.

<br/>

## 모드 결정 — 가장 먼저 정할 것

| `$ARGUMENTS` | 모드 |
|---|---|
| 비어 있음, 경로, 디렉터리, "전체" / "전부" / "스캔" | **감사** |
| 붙여넣은 한국어 산문, 제안된 재작성, "이렇게?" / "이거 어때" / "어색해" | **판정** |
| 산문 **과** 경로 | 그 항목에 **판정**, 그 다음 감사를 *제안* — 부르지 않았는데 실행하지 말 것 |
| 경로 + "내가 고친 것들 봐줘" | **감사**, 단 파일 전체가 아니라 `git diff` 범위로 |

애매하면 한 줄로 묻고 **판정** 을 기본값으로 둡니다. 원치 않은 감사는 한참 스크롤해 넘겨야 하는 긴 글이 되지만, 판정을 받은 뒤 더 넓은 검토가 필요하면 후속 질문 한 번이면 됩니다.

**비어 있으면 두 레인 모두로 해석**합니다: `git diff --name-only` (및 untracked)가 보고하는 한국어 `.md` **와** 한국어 YAML(bilingual 은 `ko:` 줄, 단일어는 값). 빈 호출을 Markdown으로만 좁히면 많은 사용자가 가장 자주 편집하는 쪽을 말없이 건너뛰게 됩니다.

<br/>

## 0단계 — 번들 사전으로 스캔

위임하기 전에 확정된 대상에 스캐너를 돌려, 에이전트가 매번 같은 후보에서 출발하게 합니다:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/scan.py" --json <file> [<file> ...]
```

- **판정 모드**: 붙여넣은 텍스트를 대신 통과시킵니다 — `printf '%s\n' '<텍스트>' | python3 "${CLAUDE_PLUGIN_ROOT}/scripts/scan.py" --stdin --json`.
- **종료 코드가 0이 아니면 멈추고 보고합니다. 그리고 이유가 둘입니다.** 사전이 깨진 경우(exit 1)에는 후보가 소리 없이 누락됩니다. **exit 3은 아무것도 스캔되지 않았다는 뜻**으로, 파일에 한국어가 있는데 레인이 한 줄도 읽지 못한 것입니다. 빈 findings는 깨끗한 파일이 아니라 레인 잘못입니다. 0이 아닌 코드로 끝난 실행을 깨끗한 스윕으로 보고하지 마세요.
- **파일마다 헤더의 `N Korean lines`를 findings보다 먼저 확인합니다.** 레인은 확장자로, `.yml` / `.yaml`은 파일 내용으로 정해집니다: `ko:` 키가 있으면 bilingual(`ko:` 절반만), 없으면 단일어 한국어(저작 값 전부, `yaml-all` 레인). `--lane md|yaml|yaml-all|text`로 바꿉니다.
- JSON을 위임 프롬프트에 넣습니다. 에이전트는 다시 돌리지 않고 그걸 씁니다.

<br/>

## 1단계 — `awkward-korean-reviewer`에 위임

레인과 모드를 한 줄로 밝힌 뒤 호출합니다. 에이전트는 패스 두 개를 돌립니다:

1. **토큰 패스** — 직역체 / 번역체 (`~에 있어서`, `~을 통해서` 남발, `의` 연쇄, 수동태 남발, 추상명사 + `~을 가지다`), 일본어식 한자어 (`검토 진행`, `~화 시키다`), AI 티 패턴 (`~하는 것이 가능`, `결론적으로`, 기계적 병렬, 이중 피동), 조사 누락·오선택, 종결법 혼용, 시제, 외래어 표기, 호응 오류, 그리고 영어 개념 1:1 치환 사전.
2. **대조 패스** — 토큰 스캔으로는 볼 수 없는 findings로, 토큰 스윕이 깨끗해도 리뷰가 끝난 게 아닌 이유입니다: **형제 구조 이탈** (형제와 모양이 다른 bullet 하나), **이웃 중복** (같은 논거를 반복하는 두 항목), **과장 드리프트** (근거는 `경감` / `방지` 인데 `최소화` / `차단` / `완전`이라고 쓴 경우), **표기 일관성** 파일 전역 (`Pod` 대 `파드`), **용어 도입 관례** (다른 개념은 전부 풀어 쓰는 산문에 맨 영어 개념어 하나).

모든 대조 finding은 근거를 함께 제시해야 합니다 — 대조한 형제 줄, 또는 두 개의 grep 카운트. 근거가 없으면 반증이 불가능하고 사용자가 확인할 수 없습니다.

<br/>

## 2단계 — 항목 단위로 적용

- **감사 모드 출력은 read-only 입니다.** 수정이 아무리 명백해 보여도 이 모드에서 편집하면 안 됩니다. 특정 항목을 적용하겠다고 제안하며 끝냅니다.
- **판정 모드는 적용 가능** — 단 전/후를 **전문으로** 보이고 (diff 조각 금지, `…` 생략 금지) 승인을 받은 뒤에만. 승인 1건은 항목 1건에만 해당하며, 파일의 나머지로는 절대 넓어지지 않습니다.
- cross-file sync는 편집의 일부입니다: 같은 `ko:` 문자열이 두 파일에 있으면 같은 턴에 둘 다 편집하거나 둘 다 편집하지 않습니다.
- YAML 편집 후에는 parse 체크를 돌리고 결과를 보고합니다.
- 커밋은 사용자가 할 다음 단계로 안내합니다. 에이전트는 커밋도, 푸시도, build 타깃 실행도 하지 않습니다.

<br/>

## 사전 키우기

토큰 패턴은 산문이 아니라 데이터입니다: `lexicon/patterns.tsv`(행마다 어색한 단어·구문 하나)와 `lexicon/terms.tsv`(한 대상의 여러 표기). 에이전트 보고서에 **사전 추가 후보** 행이 있고 사용자가 원하면:

1. 한국어 산문 일반에 통하는 행은 이 플러그인의 `lexicon/`으로 올립니다. 한 코퍼스에서만 의미 있는 행은 그 옆의 `patterns.local.tsv` / `terms.local.tsv`에 둡니다 — 이 파일의 행은 `id` / `canonical`이 같은 기본 행을 덮어씁니다. 이 파일들은 플러그인에 커밋되지 않으며, 플러그인이 갱신되면 교체됩니다.
2. `python3 scripts/scan.py --check-lexicon` — 모든 행의 `example`이 자기 `regex`에 매치해야 하고, `counterexample`은 하나도 매치하면 안 되며, `keep` 용어를 어떤 패턴도 플래그하면 안 됩니다.
3. repo 루트에서 `bash tests/run.sh`.
4. 넓은 정규식을 넣기 전에 이미 교정이 끝난 글에 돌려 hit를 읽습니다: hit가 대부분 자연스러운 한국어인 행은 정규식을 좁히거나 `min_count`를 올려야 합니다 — `N`은 한 단락, `file:N`은 파일 전체를 셉니다. 좁힌 정규식이 자연스러운 문장을 더는 잡지 않게 되면 그 문장을 행의 `counterexample` 칸(`|`로 구분)에 넣어, 나중에 정규식을 고치다가 같은 오탐이 되살아나지 않게 합니다.

에이전트는 이 파일들을 직접 편집하지 않습니다.

<br/>

## 하드 룰

- `en:` 절반, `*-en.md`, 영어 `.md`는 모든 모드에서 범위 밖입니다 — KO 변경에 맞추기 위해서라도 재작성하지 않습니다. KO 수정이 KO↔EN parity를 깬다면 그렇다고 말하고 멈춥니다.
- pair / 구조 drift (두 사본 사이의 heading 개수, 코드 블록, 표 drift)는 이 커맨드의 일이 **아닙니다** → `doc-mirror` 플러그인.
- 모든 재작성에서 사실, 숫자, 영어 기술 레이블, 코드 블록, 링크, 경로를 보존하고, 문서의 기존 톤과 register에 맞춥니다.
- 지표, 인원수, 그 어떤 숫자도 지어내지 않습니다. 사실이 틀려 보이면 flag 하되 조용히 바꾸지 않습니다.
- heading, 섹션, 리스트 항목, 표 행을 추가 / 제거 / 재정렬 / 병합 / 분할하지 않습니다. 텍스트만 다루는 패스입니다.
