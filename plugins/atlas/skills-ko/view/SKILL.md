# atlas:view — 이 프로젝트가 실제로 닿을 수 있는 것은?

세션이 한 번에 해석하는 네 개 레이어를 스캔한 뒤, 브라우저로 여는 자체완결형 HTML 파일을 쓴다 — 맵으로 만든 대상마다 하나씩.

1. 사용자 config 디렉터리 — `~/.claude`, 또는 `$CLAUDE_CONFIG_DIR`
2. 이 프로젝트 — `.claude/`, `settings.local.json`, `CLAUDE.md`, `.mcp.json`
3. 설치된 모든 플러그인 — `~/.claude/plugins/installed_plugins.json` 을 통해 해석
4. 앞의 둘에 있는 모든 settings 파일이 등록한 hook

이 skill 은 스캔하는 모든 것에 대해 **읽기 전용** 이다. 손대는 파일은 자신이 만들어내는 viewer 뿐이며, 여기에는 temp 디렉터리에 남은 자기 자신의 낡은 파일을 치우는 것이 포함된다.

<br/>

## 실행

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/atlas.py" view --open
```

이렇게 하면 temp 디렉터리에 쓰고 브라우저를 연다. 사용자가 `$ARGUMENTS` 로 준 것은 그대로 넘기고, 해당될 때 아래를 꺼내 쓴다:

| 플래그 | 쓰는 경우 |
|---|---|
| `PROJECT …` | 비교 대상으로 다른 repo 를 지목했을 때 — 아래 참고 |
| `--out FILE` | 파일을 특정 위치에 두고 싶거나, 누군가에게 보내려 할 때 |
| `--no-bodies` | config 가 커서 색인만 원할 때 |
| `--project DIR` | 작업 디렉터리 대신 *다른* repo 를 맵으로 만들 때 |
| `--keep-old` | 이전 viewer 를 그대로 두라고 했을 때 |
| `view` 대신 `scan` | 그래프를 JSON 으로 받아 파이프로 넘기려 할 때 |
| `view` 대신 `budget` | 질문이 무엇이 있느냐가 아니라 비용에 대한 것일 때 — 아래 참고 |
| `view` 대신 `diff` | 저장해둔 scan 이후 무엇이 바뀌었는지 보려 할 때 |

사용자가 숫자만 물었거나 브라우저가 도움이 안 되는 환경 — 원격 셸, 컨테이너, CI — 이면 `--open` 을 뺀다.

스크립트는 파일을 쓰는 동시에 요약을 stdout 으로 출력한다. **viewer 의 내용을 답변에 그대로 옮겨 적지 않는다** — 파일 자체가 산출물이다.

<br/>

## 다른 프로젝트와 비교하기

위치 인자는 그 프로젝트도 *함께* 맵으로 만들라는 뜻이다. 하나라도 지목하면 세 번째 맵 — 프로젝트를 스캔하지 않은 글로벌 레이어 — 이 추가되므로, `atlas.py view acme-platform` 은 파일 세 개를 낸다: 이 프로젝트, 글로벌, 그리고 저 프로젝트.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/atlas.py" view <project> --open
```

"왜 이 repo 가 저것보다 무겁지", "저 repo 에는 있는데 나한테 없는 게 뭐지" 처럼 비교하는 요청일 때 쓴다. 비교가 아니라 *다른* repo 를 맵으로 만들고 싶다면 대신 `--project DIR` 을 쓴다.

세 개를 각각의 실행 세 번이 아니라 각각이 답하는 것으로 보고한다: 글로벌 맵은 공유 기준선이고, 각 프로젝트 맵은 그 기준선에 repo 가 더한 것이다. `By scope:` 줄의 scope 별 숫자가 비교를 구체적으로 만들어 준다 — 총계 대신 그 숫자를 인용한다.

temp 디렉터리의 낡은 viewer 는 매 실행마다 정리된다. 스크립트가 `Removed stale viewer:` 줄을 출력하지 않았다면 언급하지 않고, 출력했더라도 지나가듯 한 번만 말한다.

<br/>

## 질문이 비용에 대한 것일 때

"내 context 왜 이렇게 꽉 찼지", "뭘 줄여야 하지", "그거 줄어든 거 맞나" 는 맵 질문이 아니고, 브라우저는 그 답으로 틀렸다. 두 서브커맨드가 파일을 쓰지 않고 stdout 으로 바로 답한다:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/atlas.py" budget --by kind
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/atlas.py" diff <saved-scan.json>
```

`budget` 은 상시 점유 context 가 무엇에 쓰이는지 순위를 매긴다 — `scope` / `kind` / `origin` 으로 묶고, 가장 무거운 항목을 나열한다. 상위 N 개가 아니라 임계값 이상 전부를 원하면 `--over N` 을 쓴다.

표 전체가 아니라 그 형태를 보고한다. 흔한 결론은 `CLAUDE.md` 파일이 지배적이고 다들 줄이려 드는 description 쪽이 오히려 작은 절반이라는 것이다 — 어느 버킷이 지배적인지 말하고, 열어볼 만한 항목 두세 개를 지목한다. 무엇을 삭제하라고 권하지 않는다. 무거운 항목이 그 비용값을 하고 있을 수 있다.

`diff` 는 사용자가 이미 갖고 있는 기준선을 필요로 한다. 아직 하지 않은 재작성을 측정하고 싶어 한다면, 비교를 지어내지 말고 먼저 기준선을 저장하라고 (`scan --no-bodies --out before.json`) 알려준다.

## 무엇을 보고하나

파일 경로와 스크립트가 출력한 한 줄 요약을 먼저 말하고, 아래 중 실제로 발생한 것을 덧붙인다. 짧게 유지한다.

**이름 충돌.** 실질적 결과가 있는 finding 이다. 한 agent 이름에 정의가 둘이면 세션을 어디서 시작했느냐에 따라 같은 이름이 다르게 동작하고, 어느 쪽이 이겼는지는 아무도 보고하지 않는다. 스크립트는 우선순위가 문서화된 경우 — 프로젝트 정의가 사용자 정의를 덮는 경우 — 승자를 지목하고, 그렇지 않은 경우 *ambiguous* 라고 말한다. 그 이상은 절대 추측하지 않는다.

**존재하지 않는 스크립트를 가리키는 hook.** 등록은 그대로 로드되고, hook 은 한 번도 실행되지 않으며, 아무도 그 사실을 알리지 않는다. 경로를 인용한다.

**description 이 없는 항목.** description 은 그 항목을 언제 꺼낼지 판단하는 유일한 신호다. 그것이 없으면 설치돼 있고 목록에도 있지만, 이름을 직접 대지 않는 한 도달할 수 없다.

**상시 점유 context.** 모든 command · agent · skill 의 `name` 과 `description` 은 매 세션 시스템 프롬프트에 상주하고, 모든 `CLAUDE.md` 는 통째로 상주한다 — 본문은 호출할 때만 로드된다. 그 총합이 사용자가 무언가를 입력하기도 전에 세션이 치르는 비용이다. ~5k 토큰 미만은 특별할 것 없고, ~25k 를 넘으면 매 세션의 상당 부분이 일을 시작하기도 전에 소모된다. 토큰당 4자 기준 추정치이므로 추정치로 인용한다.

**무게가 어느 scope 에 있는가.** `By scope:` 줄이 그 총합을 Global / Project / Plugins 로 쪼갠다. 어느 쪽이 지배적인지 말한다 — 모든 저장소로 따라다니는 비용과 이 저장소가 더한 비용은 다른 문제이고, 고치는 디렉터리도 다르다. 총계만으로는 둘을 구분할 수 없다.

**설치된 각 플러그인이 무엇을 더했나.** `/plugin install` 직후에는 보통 이것이 진짜 질문이다: 그 플러그인이 방금 어떤 command · agent · skill · hook 을 추가했고, 여기서 활성화돼 있는가.

<br/>

## 하드 룰

- 스캔하는 모든 트리에 대해 읽기 전용. 쓰기는 viewer 뿐이고, 삭제는 temp 디렉터리에 있는 atlas 자신의 이전 viewer 뿐이다.
- 발견한 항목을 수정 · 이동 · 삭제하지 않고, 이 skill 의 일부로 그렇게 하겠다고 제안하지도 않는다.
- 스크립트는 스캔 대상 디렉터리 안쪽의 `--out` 을 거부한다. 그 거부가 발생하면 우회하지 말고 바깥 경로를 고른다.
- 사용자가 viewer 를 repo 에 두고 싶어 하면, 그 파일이 이 머신의 실제 경로를 담고 있으므로 `.gitignore` 에 들어가야 한다고 말한다.
- 어떤 항목이 공유 가능한지 판정하지 않고, 미러된 사본끼리 diff 하지 않는다. 맵은 무엇이 어디에 있고 어디서 왔는지를 말한다.
