# session-continuity

컨텍스트 리셋을 가로질러 장기 작업을 이어 나릅니다.

> 이 문서는 [README.md](README.md)의 한국어판입니다. 내용이 어긋날 경우 영문판이 기준입니다.

```bash
/plugin marketplace add somaz94/claude-plugins
/plugin install session-continuity@somaz94
```

<br/>

## 왜 필요한가

며칠에 걸친 작업은 컨텍스트 창 하나에 들어가지 않습니다. 창이 차면 세션이 압축되거나 끝나고, 다음 세션은 아무것도 모른 채 시작합니다. 이미 내린 결정을 다시 도출하고, 이미 파악한 파일을 다시 읽고, 때로는 이미 커밋한 작업을 다시 합니다.

해법은 더 긴 창이 아닙니다. 새 세션이 실제로 필요로 하는 두 가지, 즉 **무엇이 결정됐는지**와 **다음에 무엇을 할지**를 적어 두는 것입니다. 이 플러그인이 그 두 축을 맡습니다.

<br/>

## 두 축

| 스킬 | 언제 | 무엇을 만드는가 |
|---|---|---|
| `/session-continuity:plan-update` | 의미 있는 작업 덩어리가 끝났을 때 | plan 파일을 제자리에서 갱신 — 진행 상태 전환, 결정 추가, 이력 보존 |
| `/session-continuity:handoff` | 창이 차 갈 때, 또는 하루를 마칠 때 | 새 세션에 붙여 넣을 Markdown 블록 하나 |

`plan-update`는 진행하면서 기록을 정직하게 유지하고, `handoff`는 그 기록을 읽어 진입점으로 바꿉니다. 앞의 것은 자주, 뒤의 것은 한 번 쓰면 다음 세션이 발굴 작업 대신 실제 작업부터 시작합니다.

<br/>

## 이것을 발동시키는 알림

플러그인은 `PreCompact` 훅을 함께 배포합니다. 창이 압축되기 직전 — 한계에 닿아 자동으로 압축되든, `/compact`를 직접 실행했든 — 바로 그 순간에 사실을 알리고 `/session-continuity:handoff now`를 제안합니다.

그 순간이라는 게 핵심입니다. 압축은 앞선 대화를 요약하므로, 반쯤 하다 만 편집과 어떤 결정을 내린 이유가 바로 그때 흐려집니다. Claude Code에는 컨텍스트를 특정 비율에서 알려 주는 훅이 없어서, 임박한 압축이 유일하게 쓸 수 있는 "차 간다" 신호입니다.

권유일 뿐입니다. 압축을 취소하지 않고, 세션을 열지 않으며, 핸드오프를 대신 실행하지도 않습니다. 파싱 오류가 나면 조용히 통과시킵니다 — 알림은 예의이지 경계선이 아닙니다.

<br/>

## `/session-continuity:handoff`

코드 블록 하나를 만들어 냅니다. 한 번 복사해 한 번 붙여 넣으면 됩니다. 두 가지 모드로 동작합니다.

**plan 기반**(기본): `~/.claude/plans/` 아래의 plan 파일이 기준점입니다. 프롬프트는 새 세션에게 그 파일을 먼저 읽으라고 지시하는 것으로 시작해, 다음 액션, 이미 확정된 결정, 꺼내 쓸 만한 sub-agent, 이전 세션이 남긴 `<TBD>` 항목을 차례로 담습니다.

**mid-session**: 작업 도중에 창이 차 가고 plan이 아직 없을 수도 있는 상황입니다. 이때는 진행 중이던 상태를 앞세웁니다 — 브랜치, 반쯤 편집하다 멈춘 `file:line`, 커밋되지 않은 diff, 백그라운드에서 도는 것. 여기에 이미 커밋되어 **다시 하면 안 되는** 것까지 함께 적습니다.

디스크에 없는 plan 경로를 지어내지 않고, 사용자가 답하지 않은 것을 추측하지도 않습니다. 열린 질문은 대신 결정하지 않고 `<needs user input>`으로 드러냅니다.

<br/>

## `/session-continuity:plan-update`

한 단계가 끝나거나 블로커가 풀리거나 범위가 바뀐 뒤 plan 파일을 제자리에서 고칩니다. 진행 표시를 전환하고, "무엇이 바뀌었는지" 한 줄을 덧붙이며, 작업 산출물을 구체적으로 인용합니다. 무엇이 나왔는지 가리키는 링크가 "완료"라는 단어보다 낫습니다.

번복된 결정은 **지우지 않고 덧붙입니다.** 가지 않은 길도 미래 세션에게는 plan의 가치이므로, 뒤집힌 결정에는 다시 쓰는 대신 `→ **overridden, YYYY-MM-DD**: <이유>` 흔적을 남깁니다.

plan 파일만 고칩니다. 저장소 작업 트리, `CLAUDE.md`, 에이전트 정의, 메모리 파일에는 손대지 않습니다.

<br/>

## 언어

둘 다 plan과 사용자의 메시지가 쓰인 언어를 따라 씁니다. 템플릿이 영어로 배포되는 건 무언가는 기본값이어야 하기 때문이고, 이건 *형식*이지 강제가 아닙니다. 제2 언어로 읽는 핸드오프는 절반만 읽힌 핸드오프입니다.

<br/>

## 절대 하지 않는 것

- 작업 자체를 수행하는 일. `handoff`는 다음 액션을 서술할 뿐 실행하지 않습니다.
- plan 파일을 새로 만드는 일. 그건 plan 모드의 몫이고, 이 둘은 있는 plan을 유지하고 읽습니다.
- 커밋, 푸시, 태그, 빌드 실행.
- 결정이나 파일 경로, 디스크에 없는 plan을 지어내는 일.
