# doc-mirror:check — 양쪽 다 바뀌었나?

`README.md` 옆에 `README-ko.md`를 두는 저장소에는, 둘 중 하나만 바뀌었을 때 그것을 알아채는 장치가 없다. 이 skill은 이미 어긋난 것들을 찾아낸다.

페어링 컨벤션은 **설정하는 것이 아니라 발견하는 것** 이다 — `README-ko.md`, `guide.ja.md`, `docs/setup-pt-br.md`가 모두 손대지 않아도 동작하고, 미러를 두지 않는 디렉터리에는 미러가 없다고 지적하지 않는다.

<br/>

## 실행

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/docmirror.py" .
```

| 플래그 | 쓰는 경우 |
|---|---|
| `<path>` | 작업 디렉터리가 아닌 다른 repo |
| `--json` | 리포트가 아니라 데이터로 findings가 필요할 때 |
| `--strict` | critical finding이 하나라도 있으면 non-zero 종료 — CI step 이나 배포 전 게이트용 |
| `--spacer on\|off` | 섹션 헤딩 위에 `<br/>`를 기대할지 강제 지정; 기본값은 repo가 이미 하는 방식에서 추론 |

읽기 전용. 절대 쓰지 않고, 번역하지 않으며, 없는 미러를 만들지 않는다.

<br/>

## 무엇을 보고하나

스크립트가 출력한 건수 줄을 먼저 말하고, 걸린 findings를 뒤에 붙인다. 짧게 쓴다 — 리포트는 이미 항목별로 묶여 있다.

**🔴 디렉터리 대부분이 미러를 가진 곳에서의 미러 누락.** 이 도구에서 가장 강한 신호다: 이 문서는 번역될 예정이었는데 되지 않았다. 어떤 언어인지 말하고, 스크립트가 준 비율을 인용한다 — 비율이 곧 근거이고, 비율이 없으면 그 finding은 주장에 그친다.

**🔴 깨진 상대 링크.** 고치기 쉽다. 영어 README 에서는 열리는데 한국어 README 에서는 열리지 않는 링크, 바로 이런 비대칭을 잡으려고 이 플러그인이 있다.

**🟡 구조 drift.** 헤딩 · 코드 블록 · 표 · 리스트 · 링크에서 페어가 벌어졌다. 두 숫자를 인용한다 (`headings 12 vs 6`). 원본에 섹션이 늘었는데 미러가 따라가지 못한 경우가 흔한 원인이고, 나머지는 한쪽만 통째로 다시 쓴 경우다.

**🟡 고아 미러.** 원본이 사라진 `-ko.md`. 보통 한쪽만 옮기고 다른 쪽은 두고 간 rename 이다.

**🟢 개요 순서 drift, spacer 누락, 홈 경로 링크.** 미관 문제다. 개별 항목이 아니라 건수만 언급한다.

<br/>

## 스크립트가 내릴 수 없는 판단

해당될 때는 분명히 말해야 한다. 건수만 보면 오해를 부르기 때문이다:

- **폐기한 디렉터리의 drift는 의도된 것이다.** drift finding으로 가득한 `_deprecated/` 나 `archive/` 트리는 밀린 일감이 아니다. 총계를 제시하기 전에 경로가 거기에 몰려 있는지 확인한다.
- **drift는 staleness가 아니다.** 모양이 똑같은 두 파일이 나란히 1년째 낡았을 수도 있고, 모양이 다른 두 파일이 둘 다 최신일 수도 있다. 이 도구는 구조만 잰다. "어느 쪽이 더 최근에 수정됐나" 는 커밋 히스토리를 읽는 `census drift`의 몫이다.
- **finding을 없애려고 번역하지 않는다.** 없는 미러를 만든다는 것은 용어와 톤을 결정하며 한 언어로 콘텐츠를 쓴다는 뜻이다. 사용자가 요청할 때만 초안을 제안하고, 뒷정리 삼아 해치우지 않는다.

<br/>

## 하드 룰

- 스캔 대상 전체에 대해 읽기 전용. 스크립트는 아무것도 쓰지 않는다.
- 없는 미러를 만들거나, 파일을 rename 하거나, 고아를 삭제하는 일을 스스로 판단해 하지 않는다.
- 번역이 정확한지 자연스러운지 판정하지 않는다. 이 플러그인은 의미에 대해 의견이 없고, 리포트도 마찬가지여야 한다.
- 저장소가 단일 언어를 유지한다면 그렇다고 말하고 멈춘다. "페어 없음" 은 실패가 아니라 완결된 답이다.
